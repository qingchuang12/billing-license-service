## 三、critical 问题（主流程必然故障 / 核心功能不可用）

### C1. 支付宝 Webhook 签名永远取不到 → 支付宝回调 100% 验签失败，付款后不发货

- 位置：`src/main/java/com/billing/license/controller/webhook/WebhookController.java` L83-94（`alipayWebhook` 第 91 行 `headers.get("sign")`）
- 问题：支付宝异步通知以 `application/x-www-form-urlencoded` POST 到 notify_url，**`sign` 位于请求体参数中，不在 HTTP Header**。`signature` 恒为 null → `AlipayStrategy.verifyWebhookSignature`（L195-199）直接返回 false → 回调永远 401「Invalid signature」。
- 后果：支付宝用户支付成功后永远不会签发 License/兑换码，且渠道持续重试，**主流程必然故障**。
- 修复方向：`alipayWebhook` 解析 body 参数取 `sign`（复用 `parseCallbackParams(payload).get("sign")`），并将完整参数 Map 传入验签；补端点层（header 取参）测试。
- 现存测试缺口：`WebhookControllerTest` 仅测内层 `processWebhook`，未覆盖端点层从 header 取签名的逻辑，故未暴露。

### C2. 管理端退款 100% 走失败分支（REFUND_FAILED），退款功能实际不可用

- 位置：`src/main/java/com/billing/license/service/AdminService.java` L79-115（`refundOrder`）
- 问题：`refundOrder` 用 `order.getPaymentProvider()` 解析退款渠道；grep 确认**全工程无任何调用点赋值 `order.setPaymentProvider(...)`**（`Order.java` L51-52 字段声明但从未写入）→ `resolveMethod()` 恒返回 null → 跳过渠道退款，直接 `markRefundFailed()` 抛 `REFUND_FAILED`。
- 后果：管理端退款功能实际不可用（即使渠道侧可退款），与 README 宣称不符。
- 修复方向：在 `CheckoutService.selectProvider`（或 Webhook 成功发货处）落库 `orders.payment_provider`，退款才有渠道可走。

### C3. pom.xml 缺少 Flyway 依赖 → 容器部署必崩（v1.1 补录，已修复）

- 位置：`pom.xml`（依赖清单）
- 问题：`application.yml` 配置 `spring.flyway.enabled=true`，但 pom **未引入任何 Flyway 依赖**——Spring Boot 在 classpath 无 Flyway 时静默跳过迁移，V1–V6 从未执行；`ddl-auto: validate` 随即因 `missing table [checkout_sessions]` 启动失败。**首次真实容器部署必然复现**。
- 掩盖原因：测试 profile 用 H2 `create-drop` 自动建表且 `flyway.enabled=false`，单测从不走 Flyway，故 77 测试全绿未暴露。
- 修复（已完成）：pom 新增 `spring-boot-starter-flyway`（SB4 模块化后 starter 才触发自动迁移，单独引 flyway-core 无效）+ `flyway-database-postgresql`（Flyway 10+ 将 PG 支持拆分至独立模块），版本由 Boot BOM 管理。复验：`mvn test` 全绿。
- 来源：spring-boot-starter-flyway 为 SB4 新增模块（JHU SB4 port notes、多份 SB4 集成指南）；flyway-database-postgresql 独立模块为 Flyway 10+ 要求。
