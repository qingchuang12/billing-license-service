# 产品快速接入手册

> **适用对象**：要把自己的产品（桌面端 exe / 插件 / 服务）接入本计费服务的产品、客户端与运营同学。
> **口径声明**：本手册按**当前代码实现**编写（2026-10-25）。接口字段与端点总数以 [`README.md`](./README.md)「API 接口」段和 [`接口调用时序图.md`](./接口调用时序图.md) 为准；两者冲突时以代码为准。
> **最短路径**：只想知道「配什么、调哪几个接口」→ 直接看 §0；要接订阅周期 → 必读 §6 的能力边界。

---

## 0. 最短接入路径

| # | 做什么 | 在哪里做 | 关键接口 |
|---|---|---|---|
| 1 | 定义产品（名称/描述/权益） | 管理台「产品配置 → 产品档案」 | `POST /api/admin/product-profiles` |
| 2 | 给产品建套餐（周期/双币价/授权天数） | 管理台「产品配置 → 套餐」 | `POST /api/admin/products` |
| 3 | 客户端拉在售目录 | 客户端启动或打开收银台时 | `GET /api/products?product=<产品码>` |
| 4 | 下单并选择支付渠道 | 客户端/收银台 | `POST /api/checkout/create` → `POST /api/checkout/{checkoutId}/select-provider` |
| 5 | 轮询支付结果并拿到凭证 | 客户端 | `GET /api/checkout/{checkoutId}/status` |
| 6 | 凭证落盘（三选一） | 客户端 | `GET /api/licenses/pending` / `POST /api/licenses/activate` / `POST /api/licenses/report-binding` |
| 7 | 已购授权持续有效性验证 | 客户端启动 + 按服务端节奏（默认 15 天） | `GET /api/licenses/verify/{licenseKey}` |

成功标志：客户端拿到 `signedToken` 并本地验签通过，且**周期性在线复核持续返回 200**（见 §5.5）。

## 1. 两层模型：产品档案 vs 套餐

```
产品档案 product_profiles          套餐 products
(product_code 唯一)         1 ── n (sku 唯一)
 名称 / 描述 / 权益 features        周期 / 双币价 / 档位 / 授权天数 / 推荐位
```

- **权益只属于产品**：同一 `product_code` 下的月付、半年、年付、永久套餐**共享同一份权益清单**；改档案权益会对该产品下所有套餐立即生效。
- **套餐是售卖单元**：一个 SKU 对应一个价格与一个计费周期；License 按 SKU 签发。
- **一个产品可以有多个周期**：例如 `ai-tools` 下 `ai-tools-monthly`、`ai-tools-half-year`、`ai-tools-yearly`、`ai-tools-buyout` 四个 SKU，同权益、不同周期与价格。

## 2. 配置产品与套餐（运营 / 管理员）

以下接口均需管理员登录后的 `Authorization: Bearer <JWT>`（`role=ADMIN`）。也可以用管理台界面操作，字段与接口一致。

### 2.1 建产品档案

`POST /api/admin/product-profiles`

| 字段 | 必填 | 说明 |
|---|---|---|
| `productCode` | 是 | 1–64 位字母/数字/短横线；**创建后不可修改**（套餐以它为关联键） |
| `name` | 是 | 中文产品名，≤255 字 |
| `nameEn` | 否 | 英文产品名（收银台双语展示） |
| `description` / `descriptionEn` | 否 | 产品描述（中/英） |
| `features` | 否 | 权益键数组，如 `["OFFLINE","MULTI_DEVICE"]`；键须匹配 `^[A-Z][A-Z0-9_]*$` |

```bash
curl -X POST http://localhost:8000/api/admin/product-profiles \
  -H "Authorization: Bearer $ADMIN_JWT" -H "Content-Type: application/json" \
  -d '{"productCode":"ai-tools","name":"AI Tools","nameEn":"AI Tools",
       "features":["OFFLINE","MULTI_DEVICE"]}'
```

- 可用的权益键与中英文显示名由 `billing.feature-labels` 配置（`GET /api/admin/products/meta` 会返回 `features` 列表，管理台表单据此渲染）。
- 权益键只做格式校验，**不强制**必须是配置里已有的键；但用了未配置的键，收银台会直接显示原始键。

### 2.2 建套餐

`POST /api/admin/products`（`PATCH /api/admin/products/{productId}` 改配置，`PATCH .../active` 上下架）

| 字段 | 必填 | 说明 |
|---|---|---|
| `sku` | 是 | 2–64 位字母/数字/短横线，全局唯一；**创建后不可修改** |
| `productCode` | 是 | 必须指向**已存在**的产品档案，否则 `PRODUCT_PROFILE_NOT_FOUND` |
| `name` / `nameEn` | 名称必填 | 套餐展示名（收银台卡片标题） |
| `description` / `descriptionEn` | 否 | 套餐描述 |
| `priceCny` / `priceUsd` | **都必填** | 国内价（CNY）与国际价（USD），均 >0、最多 2 位小数；缺任一档该区域下单会直接拒绝（`PRICE_NOT_CONFIGURED`，不跨币种回退） |
| `billingCycle` | 是 | `ONE_TIME` / `MONTHLY` / `HALF_YEAR` / `QUARTERLY` / `YEARLY` / `LIFETIME` |
| `tier` | 是 | `PRO` / `PRO_PLUS`（写进 License 的 `plan`） |
| `licenseDurationDays` | 是 | 1–36500；License 过期时间 = 签发时间 + 该天数。月付常用 31，年付 365，买断常用 3650 |
| `updateUntilDays` | 否 | 更新权益截止天数（写 `update_until`）；空或 ≤0 = 不限制 |
| `maxMajorVersion` | 否 | 可用大版本上限（写 `max_major_version`）；空或 ≤0 = 不限制 |
| `recommended` | 否 | 收银台「推荐」徽标；纯展示，可多个 |
| `active` | 否 | 仅新增时生效，默认 true；上下架走独立端点 |

```bash
curl -X POST http://localhost:8000/api/admin/products \
  -H "Authorization: Bearer $ADMIN_JWT" -H "Content-Type: application/json" \
  -d '{"sku":"ai-tools-monthly","productCode":"ai-tools","name":"AI Tools 月付",
       "priceCny":19.90,"priceUsd":2.99,"billingCycle":"MONTHLY","tier":"PRO",
       "licenseDurationDays":31,"recommended":true}'
```

注意事项：

- `products.price` / `products.currency` 是历史兼容列，由服务端在保存时自动与 `priceUsd` / `USD` 同步；**不要绕过接口直接改库**，否则会漂移。
- 不提供物理删除：订单、License、兑换码都外键引用套餐。停售请用 `PATCH /api/admin/products/{productId}/active`（只影响新订单，已签发的 License 不受影响）。
- 改价格/周期同样只影响新订单，不会追溯已签发 License。

## 3. 拉取在售目录

`GET /api/products?product=<产品码>`（公开，无需鉴权）

- `product` 缺省或空白 = 全部在售（`active=true`）套餐；大小写不敏感。
- **返回顺序固定**：推荐位在前，其余按 SKU 升序。
- 响应是数组（外层为统一响应壳，见 §8）。

| 字段 | 说明 |
|---|---|
| `sku` / `productCode` | 下单用的 SKU 与所属产品码 |
| `name` / `nameEn` / `description` / `descriptionEn` | 展示文案 |
| `priceCny` / `priceUsd` | 双币价（下单按区域取用） |
| `billingCycle` | 计费周期枚举 |
| `recurring` | **是否订阅类周期**（`MONTHLY` / `HALF_YEAR` / `QUARTERLY` / `YEARLY` 为 true；`ONE_TIME` / `LIFETIME` 为 false）——客户端据此展示「自动续费」与到期提示 |
| `providers` | **当前部署下可售该套餐的渠道**：`[{method, region, supportsRecurring, supportedBillingCycles, paymentProducts}]`；按渠道能力矩阵过滤，只含已启用渠道；空数组＝当前无渠道可售（客户端应置灰该套餐） |
| `tier` | `PRO` / `PRO_PLUS` |
| `licenseDurationDays` | 授权有效天数 |
| `updateUntilDays` / `maxMajorVersion` | 更新权益截止天数 / 大版本上限；null = 不限制 |
| `recommended` | 是否推荐位 |
| `features` | 权益原始键数组（产品档案） |
| `featureViews` | 权益的中英文显示名 `{key,labelZh,labelEn}`，收银台直接渲染 |

## 4. 下单

### 4.1 两段式（推荐，交互可控）

**第一步**：`POST /api/checkout/create`

```json
{
  "productId": "ai-tools-buyout",
  "currency": "CNY",
  "locale": "zh-CN",
  "machineId": "5E01-7EB8-3661-E06A",
  "customerEmail": "buyer@example.com",
  "returnUrl": "https://app.example.com/pay/success",
  "cancelUrl": "https://app.example.com/pay/cancel"
}
```

返回：

```json
{ "success": true, "code": "SUCCESS",
  "data": { "checkoutId": "chk_9F8E7D6C5B4A1234", "orderNumber": "ORD-...",
            "status": "CREATED", "paymentMethods": ["ALIPAY","WECHAT_PAY"],
            "payUrl": "", "expiresAt": 1761234567890 } }
```

**第二步**：`POST /api/checkout/{checkoutId}/select-provider`

```json
{ "provider": "alipay" }
```

返回按渠道给出 `paymentMode`：

- `qrcode`：`qrcode` 字段是要渲染成二维码的内容；
- `redirect`：跳 `payUrl`（或 `redirectUrl`）。

`provider` 取值：`alipay` / `wechat_pay` / `stripe` / `paddle` / `paypal`（不区分大小写）。渠道是否可用由服务端配置决定，未启用会返回 400。

**一步式**：`create` 请求里直接带 `provider`，服务端建单后立即创建支付并返回二维码/跳转链接，省一次往返。渠道创建失败时订单与会话会保留（可换渠道继续），同时返回 `PAYMENT_CREATE_FAILED`。

### 4.2 区域定价与渠道能力过滤

- `currency=CNY` 或 `locale` 以 `zh` 开头 → 国内：取 `priceCny`，可用渠道为支付宝/微信；
- 其余 → 国际：取 `priceUsd`，可用渠道为 Stripe/Paddle/PayPal。
- 目标区域价缺失 → `PRICE_NOT_CONFIGURED`，不会跨币种回退。
- **渠道能力过滤**：建单只返回「已启用且支持该套餐周期」的渠道。国内两家只支持一次性买断（`ONE_TIME` / `LIFETIME`），**订阅周期套餐在国内区域会得到 `NO_PAYMENT_METHOD`**；订阅周期只在国际的 Stripe / Paddle 可售。选渠道时若能力不匹配，返回 `PROVIDER_NOT_SUPPORTED_FOR_PLAN`。

### 4.3 会话生命周期与轮询

- 收银台会话有效期 **2 小时**；过期后不再做主动查单补偿，清理任务（默认每小时）删除后 `GET /status` 返回 `CHECKOUT_NOT_FOUND`。
- 轮询 `GET /api/checkout/{checkoutId}/status`；未支付时服务端会主动向渠道查单（**冷却 30 秒**：30 秒内重复轮询不会重复打渠道），因此建议 **3–5 秒轮询一次**即可。
- 会话 `status` 流转：`CREATED` → `PENDING` → `PAID`。
- `PAID` 后响应里带 `license`（已绑机器码）或 `redeemCode`（未传机器码）。

### 4.4 幂等与重试（重要）

| 动作 | 幂等性 | 客户端该怎么做 |
|---|---|---|
| `create` | **不幂等**：每次调用都新建订单与会话 | 不要自动重试；超时/失败时先查已有 `checkoutId` 的状态，确需重来再重新下单 |
| `select-provider`（同一 `checkoutId`、同一渠道） | 幂等：复用已创建的支付入口 | 用户连点/前端重试可直接调用 |
| `select-provider`（已支付会话） | 幂等：直接返回已支付状态 | — |
| 支付回调 | 服务端按渠道事件 ID 去重 | 客户端无需处理 |
| `status` 补偿查单 | 幂等：订单状态机 + 订单行锁 | — |

> 收银台下单有 **IP + 邮箱双维度限流**：同一邮箱购买频控、同一 IP 下单频控，命中分别返回 `EMAIL_PURCHASE_LIMIT` / `CHECKOUT_IP_LIMIT`。

## 5. 支付完成后拿到凭证

### 5.1 三种交付形态

| 下单时是否带 `machineId` | 支付成功后服务端 | 客户端如何拿凭证 |
|---|---|---|
| **带** | 直接签发绑定该机器码的 License，并发出「支付成功 + License Key」两封邮件 | `GET /status` 返回 `license`（signedToken）；或 `GET /api/licenses/pending?machineId=` |
| **不带** | 生成兑换码并发邮件 | `GET /status` 返回 `redeemCode`；用户在客户端输入后调 `POST /api/licenses/activate` |

邮件发送是异步的，且未配置 SMTP 时自动跳过，**不能把邮件当作唯一交付通道**。

### 5.2 待领取授权（客户端自动到账）

`GET /api/licenses/pending?machineId=<本机机器码>`（公开，机器码 + IP 双维度限流）

- 返回最近 **7 天**（`billing.pending-license-window-days`）内签发、`ACTIVE`、绑定本机且**从未在线校验过**的授权；
- 响应 `{ licenses: [{licenseKey, signedToken, productSku, expiresAt, issuedAt}], serverTime }`；
- 只读：领取动作仍由客户端落盘 + `report-binding` 完成；
- 触发限流时返回 **429 空 body**。

建议客户端在支付成功后 60 秒内按 2–3 秒间隔轮询本端点，命中即落盘。

### 5.3 激活与补绑

**兑换码/许可证密钥激活**：`POST /api/licenses/activate`

```json
{ "code": "RC-8F3C-1D2E-9A4B", "customerEmail": "buyer@example.com", "machineId": "5E01-7EB8-3661-E06A" }
```

- `code` 传兑换码（`RC-` 前缀）时匿名可调；
- 传许可证密钥时**必须登录且归属本人**；
- 成功返回 `{success, licenseKey, signedToken, status, machineId, expiresAt, serverTime}`。

**启动时补绑**：`POST /api/licenses/report-binding`

```json
{ "signedToken": "<激活时拿到的 signedToken>", "machineId": "<本机机器码>" }
```

用于「先付款后装客户端 / 激活时没带机器码」的场景：凭签名令牌验签，无需登录。绑定以 `licenses.machine_code` 为唯一真相。

### 5.4 在线校验与离线验签

- 在线校验：`GET /api/licenses/verify/{licenseKey}`（公开，限流）。成功返回 License 详情 + `nextCheckAfterMs`（默认 360 小时 = 15 天，配置 `billing.license-check-interval-hours`），并把 `lastVerifiedAt` 更新为本次成功时间。
- 失败返回 **HTTP 400**：`LICENSE_NOT_FOUND`（密钥不存在）、`LICENSE_EXPIRED`（已过期，服务端同时把状态置 `EXPIRED`）、`LICENSE_INVALID`（已吊销 / 已换机重发 / 签名校验失败等一切非 `ACTIVE` 状态）；限流返回 **429 空 body**。
- 离线验签：`signedToken` 是 JWS 三段式，客户端用公钥验签，并按 payload 校验 `mid` / `exp` / `plan` / `feat`。

payload 字段：

| 键 | 含义 |
|---|---|
| `lic` | License Key |
| `cid` | 客户 ID |
| `sku` | 套餐 SKU |
| `plan` | 档位 `PRO` / `PRO_PLUS` |
| `feat` | 权益键数组（来自**产品档案**） |
| `mid` | 绑定的机器码 |
| `oid` | 订单 ID |
| `iat` / `exp` | 签发时间 / 过期时间（epoch 秒）；永久授权无 `exp` |
| `update_until` | 更新权益截止时间（epoch 秒）；缺失 = 不限制 |
| `max_major_version` | 可用大版本上限；缺失 = 不限制 |
| `meta` | 可选扩展 |

### 5.5 已购 License 的持续有效性验证（拿证之后必接）

> 拿到 `signedToken` 只代表「签发那一刻有效」。退款、吊销、换机重发、订阅到期、设备变更都发生在拿证之后——不做持续验证，这些变化客户端永远发现不了。

**三层验证，缺一不可：**

| 层 | 时机 | 做法 | 失败处置 |
|---|---|---|---|
| 本地验签 | 每次启动、每次读取授权 | 公钥验 `signedToken`；比对 payload 的 `mid` = 本机机器码、`exp` 未过、`plan`/`feat` 命中所需权益 | 验签失败或机器码不符 → 停用；换机走 §7 的换机重发 |
| 在线复核 | 启动后 + 按 `nextCheckAfterMs` 排期（默认 15 天） | `GET /api/licenses/verify/{licenseKey}` | 见下方「明确无效」与「问不到」 |
| 时间防回拨 | 每次复核 | 用 HTTP `Date` 响应头抬高校验下界（**该端点不返回 `serverTime`**），只升不降 | 回拨不能让过期授权复活，也不能跳过宽限 |

**排期规则：**

- `nextCheckAfterMs` 由服务端下发（取自 `billing.license-check-interval-hours`），**不要硬编码间隔**，服务端调参即生效。
- 把下次复核时间持久化，跨重启存活；重启不应重置为「立刻复核」或「永远不复核」。
- 对下发值做合理夹取（参考客户端口径 `[1 小时, 30 天]`），异常值不应把节奏打乱。

**失败与宽限（以下 2 小时 / 30 天 / 60 天是客户端策略，服务端只给结论，不强制）：**

| 情形 | 性质 | 客户端动作（参考 `ai-tools` 现行口径） |
|---|---|---|
| `LICENSE_EXPIRED` / `LICENSE_INVALID` | 服务端**明确**答无效 | **立即停用**，不消耗宽限；引导续费或重新激活 |
| 网络错误 / 5xx / 429 空 body / 响应畸形 | 问不到 | 2 小时后重试；429 另加 0–10 分钟抖动，继续累计离线宽限 |
| 连续 30 天没有一次成功复核 | 提醒态 | 功能不减，提示用户联网复核 |
| 连续 60 天没有一次成功复核 | 软失效 | 停止付费功能；**不清 token、不清激活信息**，复网复核成功即自愈 |
| 启动时本次进程尚未复核过 | 保护期 | 不因「上次成功时间过久」直接停用，先放行并立即发起本次复核 |

**六个必须注意的坑：**

1. **verify 不校验机器码**：它只按 `licenseKey` 查状态；`mid` 必须客户端自己比对，否则等于放弃设备绑定。
2. **吊销与换机重发返回的是 `LICENSE_INVALID`**，不是 `LICENSE_REVOKED`；只匹配 `LICENSE_REVOKED` 会漏掉吊销。
3. **复核停用的优先级必须高于硬件变更宽限**：否则「退款用户换块硬盘」就能再拿 7 天。先判复核结论，再走换机宽限。
4. **时间基准只认服务端**：本地 `Date.now()` 可被用户修改；激活/领取端点有 `serverTime`，verify 只能用 HTTP `Date`。
5. **停用是软失效**：保留 token 与激活信息，复网复核成功即恢复；不要做删库式清理，否则用户必须重新输入密钥。
6. **服务端不主动推送失效**：没有失效通知/推送通道；`EXPIRED` 只在 verify 命中过期或订阅事件驱动时落库。客户端必须自己排期复核，不能等推送；未复核的证在库里可能仍显示 `ACTIVE`，但本地 `exp` 校验与在线复核都会拦截。

**最小伪代码：**

```text
onAppStart:
  token = vault.load()
  if !verifySignature(token) || token.mid != localMachineCode || expired(token) -> deactivate()
  if now >= nextCheckAt -> recheck()

recheck():
  resp = GET /api/licenses/verify/{licenseKey}
  if 200:
      nextCheckAt = now + clamp(resp.nextCheckAfterMs, 1h, 30d)
      serverFloor = max(serverFloor, httpDateHeader(resp))   // 只升不降
      lastVerifiedOkAt = now
  else if 400 and code in (LICENSE_EXPIRED, LICENSE_INVALID):
      disableImmediately()                                   // 权威无效，不吃宽限
  else:
      nextCheckAt = now + 2h + jitter
      if daysSince(lastVerifiedOkAt) >= 60 -> softDisable()  // 保留 token，可自愈
      else if daysSince(lastVerifiedOkAt) >= 30 -> remindOnly()
```

## 6. 订阅周期：收银台真订阅与能力边界（必读）

**先看结论**：`billingCycle` 的 `MONTHLY` / `HALF_YEAR` / `QUARTERLY` / `YEARLY` 是「订阅类周期」，续费与取消由 **Paddle / Stripe 托管**。收银台**按套餐周期直接开出渠道侧订阅**——用户付完首期就进入自动续费，**不需要在渠道后台手工预建订阅对象**。

### 6.1 两家渠道的开法不同（配置要求不一致）

| 渠道 | 开订阅的方式 | 套餐要配什么 |
|---|---|---|
| Stripe | Checkout Session 走 `mode=subscription` | **可不配**：按周期内联 recurring price（月=1 月、季=3 月、半年=6 月、年=1 年）。要复用渠道后台既有价目时填 `stripePriceId`（`price_` 前缀） |
| Paddle | 交易带 catalog `price_id`，Paddle 自动建订阅 | **必须配** `paddlePriceId`（`pri_` 前缀）。Paddle 不认内联价目，订阅周期缺这个 id 直接拒单（`PADDLE_PRICE_ID_MISSING`），不会静默降级成一次性收款 |

一次性买断（`ONE_TIME` / `LIFETIME`）维持原样：Stripe `mode=payment`、Paddle ad-hoc 价目；两个 price id 字段留空即可，填了也不生效。

### 6.2 续费为什么能找到订单

下单时服务端把订单号写进渠道的订阅对象（Stripe 写 `subscription_data.metadata.order_id`，Paddle 写交易 `custom_data.order_id` 并由 Paddle 带到自动创建的订阅上）。后续 `invoice.paid` / `transaction.billed` / `subscription.*` 事件因此都能回查到本站订单，续期与取消自动关联到那张 License。

### 6.3 其余边界

1. **国内渠道（支付宝/微信）没有订阅能力**：订阅周期套餐在国内区域**不会出现在可选支付方式里**，建单直接返回 `NO_PAYMENT_METHOD`；这不是故障，是渠道能力矩阵按设计拦截。要卖订阅周期必须走国际区域（Stripe / Paddle）。
2. **续费联动**：收到成功事件时把已绑定 License 的 `expiresAt` 取 `max(现有到期时间, 渠道周期结束时间)`，重复投递不累加。
3. **取消 = 期末失效**：`currentPeriodEnd` 在未来则权益保留到该时点，否则立即失效；`CANCELED` 是终态，迟到的成功事件不会把订阅复活。
4. **未带机器码的订阅订单**：首期发兑换码；用户兑换后签发的 License 会**挂回原订单**，续费与取消能找到这张证。但用户**一直不兑换**则没有可联动的 License，续费只会累积订阅记录、不延长任何证。
5. **首充回调丢失可自愈**：服务端会到渠道反查订阅补建记录，见 §9。

## 7. 退款、换机与解绑

| 场景 | 入口 | 规则 |
|---|---|---|
| 用户自助退款 | `POST /api/account/orders/{orderNumber}/refund`（需登录） | 按 License 剩余有效期线性折算；**订阅类订单不开放自助退款**；单笔折后金额低于 `billing.refund.min-amount`（默认 1.00）不可退；同一用户 60 分钟内最多 5 次 |
| 管理员退款 | `POST /api/admin/orders/{orderNumber}/refund` | 全额退；渠道退款成功才本地置 `REFUNDED` 并吊销 License，渠道失败置 `REFUND_FAILED` 保留 `PAID` 待人工处理 |
| 渠道退款回调 | `POST /api/webhooks/*` | 渠道侧退款/取消事件自动吊销该订单下 License |
| 用户自助解绑 | `POST /api/account/licenses/{licenseKey}/unbind`（需登录） | 只清设备绑定，保留授权 |
| 管理员换机重发 | `POST /api/admin/licenses/{licenseKey}/reissue` | 可指定 `newMachineId`；有重发次数上限，`force=true` 可越限 |
| 管理员作废 | `POST /api/admin/licenses/{licenseKey}/revoke` | 立即失效 |

注意：订阅订单的「取消订阅」不通过本服务发起（渠道侧无取消 API），本服务只处理入向取消事件。

## 8. 响应壳与错误码

除 Webhook 与 springdoc 外，所有响应统一为：

```json
{ "success": true, "code": "SUCCESS",
  "data": { }, "traceId": "a1b2c3d4e5f6a7b8", "timestamp": "2026-10-25T21:00:00" }
```

> 成功时 `message` 不出现（`NON_NULL` 序列化）；业务失败时 `success=false`、`code` 为错误码、`message` 为可读文案、`data` 不出现。

业务失败返回 **HTTP 400** + `success=false`，`code` 为下列错误码；`traceId` 用于排查（服务端日志同 ID）。

### 收银台 / 目录

| code | 含义 | 客户端处理 |
|---|---|---|
| `PRODUCT_NOT_FOUND` | SKU 不存在 | 刷新目录 |
| `PRODUCT_INACTIVE` | 套餐已下架 | 刷新目录/换套餐 |
| `PRICE_NOT_CONFIGURED` | 该区域未配置价格 | 提示暂不可售 |
| `NO_PAYMENT_METHOD` | 该区域/该套餐周期无可用渠道（常见：国内买月付） | 提示或联系运营 |
| `PROVIDER_REQUIRED` / `UNSUPPORTED_PROVIDER` | 未传/非法渠道 | 修正参数 |
| `PROVIDER_NOT_SUPPORTED_FOR_PLAN` | 该渠道不支持此套餐的计费周期（如支付宝买月付） | 改选目录 `providers` 里列出的渠道 |
| `PAYMENT_CREATE_FAILED` | 渠道下单失败 | 可换渠道重试（订单保留） |
| `CHECKOUT_NOT_FOUND` | 会话不存在/已过期 | 重新下单 |
| `CHECKOUT_IP_LIMIT` / `EMAIL_PURCHASE_LIMIT` | 触发限流 | 退避后再试 |

### 凭证 / License

| code | 含义 |
|---|---|
| `CREDENTIAL_NOT_FOUND` | 兑换码/许可证密钥无法识别 |
| `CODE_ALREADY_USED` / `CODE_EXPIRED` | 兑换码已用/已过期 |
| `REDEEM_IP_LIMIT` / `REDEEM_BRUTE_FORCE` | 兑换频控 / 猜测锁定 |
| `MACHINE_MISMATCH` | 已绑定其它设备 |
| `MACHINE_ID_REQUIRED` / `MACHINE_ID_INVALID` | 机器码缺失/非法 |
| `LOGIN_REQUIRED` | 用许可证密钥激活但未登录 |
| `LICENSE_EXPIRED` / `LICENSE_INVALID` / `LICENSE_NOT_FOUND` | 在线校验失败原因（吊销/换机重发在 verify 中统一返回 `LICENSE_INVALID`） |

### 产品配置（管理员）

`PRODUCT_PROFILE_EXISTS` / `PRODUCT_PROFILE_NOT_FOUND` / `PRODUCT_PROFILE_CODE_IMMUTABLE` / `SKU_EXISTS` / `SKU_IMMUTABLE` / `SKU_REQUIRED` / `INVALID_BILLING_CYCLE` / `INVALID_PLAN_TIER` / `INVALID_FEATURE_KEY` / `VALIDATION_ERROR`。

## 9. 排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 目录里没有新套餐 | 套餐 `active=false`，或客户端传错 `product` | 管理台确认上下架；`GET /api/products?product=<码>` 直接看返回 |
| 下单报 `PRICE_NOT_CONFIGURED` | 只配了单边价 | 补 `priceCny` / `priceUsd` |
| 国内下单月付套餐报 `NO_PAYMENT_METHOD` | 渠道能力矩阵拦截：国内渠道只支持一次性买断 | 按月付只在英文界面（国际区域）售卖，或把国内套餐改为买断 |
| 套餐在目录里 `providers` 为空 | 该周期没有任何已启用渠道 | 启用 Stripe/Paddle（订阅周期）或在管理端改周期 |
| 下单后拿不到二维码 | `provider` 对应渠道未启用（缺密钥/未加入 `PAYMENT_ENABLED_CHANNELS`） | `GET /api/admin/payment-channels` 自查缺失配置项 |
| `status` 一直 `PENDING` | 渠道回调未达，或补偿冷却中 | 3–5 秒轮询；超过 2 小时会话过期需重新下单 |
| 支付成功但客户端没收到 License | 未调 `pending`，或客户端机器码与下单时不一致 | 用**下单时的机器码**调 `pending`；不一致则走 `activate` 的密钥分支或换机重发 |
| 续费后 License 没延长 | 订阅未绑定到这张证（无机器码且一直未兑换） | 查 `subscriptions` 表是否有记录、`license_id` 是否为空 |
| 日志出现「已按渠道查询自动重修」 | 首充回调丢失，服务端已到渠道反查订阅并补建记录 | 无需处理，属自愈路径；核对补建的订阅绑到了正确订单即可 |
| 日志出现「需人工补录」 | 首充回调丢失**且**渠道反查没取到订单号（订阅在渠道侧已删除，或下单时未写入 order_id） | 按日志 `subId` 到渠道后台查出对应订单号后人工补录订阅记录 |
| 订阅套餐下单报 `PADDLE_PRICE_ID_MISSING` | Paddle 只认 catalog 价目 id，套餐没配 | 管理台给套餐补 `paddlePriceId`（`pri_` 前缀），或改走 Stripe 渠道 |
| 用户取消订阅后权益还在 | 正常：期末失效，权益保留到 `currentPeriodEnd` | 到该时点自动失效 |
| 退款/吊销/换机后客户端仍能用 | 客户端没做已购授权复核，或只匹配了 `LICENSE_REVOKED` | 按 §5.5 接入定期 verify；吊销与换机返回 `LICENSE_INVALID` |
| 接口返回 429 空 body | 触发了公开端点频控（verify / pending / activate） | 退避重试，勿密集轮询 |

## 10. 接入自检清单

- [ ] 产品档案已建，`productCode` 与客户端写死的产品码一致；
- [ ] 每个要卖的周期都有独立套餐，`priceCny` / `priceUsd` 都填了；
- [ ] `GET /api/products?product=<码>` 返回的 `recurring` 与产品形态一致（买断 false、订阅 true），`providers` 与预期渠道一致；
- [ ] 客户端按 `providers` 置灰不可售套餐，不做「先让用户选、提交时才报错」；
- [ ] 客户端保存了 `checkoutId`，不对 `create` 做自动重试；
- [ ] 支付成功后有 `pending` 轮询或兑换码激活兜底；
- [ ] `signedToken` 已落盘并本地验签，`machineId` 与 `licenses.machine_code` 一致；
- [ ] 已实现**启动验签 + 定期在线复核**：排期用服务端 `nextCheckAfterMs`（默认 15 天）并跨重启持久化（§5.5）；
- [ ] 复核收到 `LICENSE_EXPIRED` / `LICENSE_INVALID` 会立即停用；网络失败按 2 小时重试并累计宽限（30 天提醒 / 60 天软失效），复网自愈；
- [ ] 停用/宽限的时间基准用服务端时间（verify 用 HTTP `Date`），不用本地 `Date.now()`；
- [ ] 订阅产品已确认：国内渠道无自动续费，只在 Stripe / Paddle 售卖；走 Paddle 的订阅套餐已配 `paddlePriceId`，走 Stripe 的按周期自动内联价目（§6.1）；
- [ ] 邮件送达不是唯一交付通道（SMTP 未配置时会跳过）。
